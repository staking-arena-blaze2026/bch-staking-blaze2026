2. **Provider verification.** All three hosts are evaluated. At least two must independently verify identical current action-relevant evidence at the latest observed tip. Linked headers prove ordinary extension/lag; inputs, tokens, raw bytes, merkle proofs and ancestry remain checked. A verified conflicting spend, branch conflict or within-read tip retreat blocks signing. Proved chain conflicts survive provider outages and browser reloads until compatible independent evidence resolves them. Retries are bounded and rebuild reads. Majority agreement alone is insufficient.
3. **Discovery architecture.** The deployed static frontend reads the already-running public Electrum script-history index. Its marker script is `a914da1745e9b549bd0bfa1a569971c77eba30cd5a4b87`; RPC scripthash is `0a13081785a298b8b9dc427343ee7252e963361394f4b196aaad918e85315fb0`. Discovery returns hints; the separate blockchain replay establishes financial state. Pages fetch at most 20 announcement candidates by default, with a cursor; the marketplace displays/replays 20 vaults per page.
4. **New vault publication.** Direct genesis or the existing chained/legacy preparation transaction carries a fixed public marker and canonical immutable parameter metadata. Electrum automatically indexes it. No creator JSON submission, extra approval or separate publication transaction is needed. The explicitly disclosed marker is 1,000 satoshis spendable by anyone, separate from the unchanged 10,000-satoshi miner fee per transaction. Atomic offer policy and ownership checks remain intact.
5. **Historical recovery.** The shared seed catalog includes `fa5bae8625e61ec15a9d1527157f1e544d6d4bee9a1a268095099320e33e8c86` with the supplied immutable BCH/BCH parameters. It is independently replayed. Existing signed creation journals repopulate public configurations; saved/imported configurations persist independently of wallet connection and verification. Restoring a listing requires no transaction. This is explicitly an incomplete historical index.
6. **0-conf and reorgs.** Independently verified pending lineage is provisional. Confirmation and journal status changes refresh listings. Eviction, conflicting state or reorg invalidates current authority while configurations and stale, clearly labeled snapshots remain visible. Failed verification disables financial actions. Signed transaction bytes remain recoverable; retries retain identical transactions.
